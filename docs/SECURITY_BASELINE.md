**Last Audited:** 2026-11-17  
**Scope:** Application codebase in `/app/applet` (`src/`, `worker/`, `server.ts`, `migrations/`, `scripts/`)

Every future code or infrastructure change to SELLORA must be checked against this baseline before and after modification.

## 2. Confirmed Target Security Specifications *(Pending Implementation — Not Yet Enforced in Live Code)*

The following requirements extend SELLORA's security model without removing or weakening any existing customer or Better Auth control:

| Requirement | Specification & Security Invariants *(Implemented Locally — Remote Deployment Pending)* | Components |
| :--- | :--- | :--- |
| **B. Separate Admin Security Password** | 1. Normal admin authentication (Email/Password or Google OAuth) remains mandatory as the first factor.<br>2. Before granting Admin Dashboard UI or `/api/admin/*` API access, the admin session must verify a **separate admin security password**.<br>3. Stored ONLY as a strong salted `scrypt` hash (`N=16384, r=8, p=1, dkLen=64`, 16-byte salt, constant-time `timingSafeEqual`; zero plaintext storage or logs).<br>4. Rate-limited with persistent temporary lockout protection on failed verifications (fail-closed on DB errors).<br>5. Verification state is strictly **session-bound** (`session_id`) and expires per policy (idle/max security TTL, revoked on logout/device change/IP lock).<br>6. Safe initial setup (for existing owner/staff accounts without locking them out permanently on rollout), authenticated password change (requiring current password + recent primary auth), and out-of-band/owner recovery flow. | `migrations/0007_*`, `src/server/crypto.ts`, `src/server/admin-security.ts`, `src/server/routes/admin.ts`, `AdminDashboard.tsx`, `AdminSettingsTab.tsx` |
| **C. Strict Unfamiliar-Device & IP Lock Policy (Admin Accounts)** | 1. Policy is **STRICT** for privileged admin accounts (`role !== 'customer'`): **an unfamiliar device OR an unfamiliar IP address triggers an immediate fail-closed security lock** denying dashboard access (`423` `ADMIN_SECURITY_LOCKED`) while locked.<br>2. Device recognition uses a cryptographically random, server-issued `HttpOnly; SameSite=Lax` (`Secure` in HTTPS) device cookie (hashed with SHA-256 in `admin_trusted_devices` alongside browser/OS metadata and `trusted_ip`) rather than User-Agent-only hashing (`computeDeviceHash` alone is insufficient against spoofing).<br>3. All login attempts and recognized devices are recorded; suspicious/locked attempts create `SEC-XXXXXXXX` alerts and `audit_logs`.<br>4. Customer login-monitoring behavior remains non-disruptive (`login_history`, `known_user_devices`) while privileged admin sessions enforce strict pre-dashboard locking. | `src/server/login-monitor.ts`, `src/server/admin-security.ts`, `src/server/routes/admin.ts`, `src/server/app.ts` |
| **D. Scanner-Safe Gmail Approval Workflow** | 1. Triggered whenever an unfamiliar device or unfamiliar IP places an admin session into a security lock.<br>2. Sends alert email via Brevo outbox (`email_notification_events`) to registered admin Gmail (`OWNER_EMAIL` / `ADMIN_NOTIFICATION_EMAIL`) containing alert explanation, login attempt time (UTC & WAT), device/browser & IP/location summary, and **`YES — APPROVE ACCESS`** / **`NO — REJECT ACCESS`** actions.<br>3. **Email Scanner Protection**: Email links point to `GET /api/security/admin-approval?action=...&token=...`, which ONLY displays an explicit HTML confirmation screen and **never modifies DB state on `GET`**. Decision executes only upon explicit `POST /api/security/admin-approval` submission.<br>4. **Token Security**: Short-lived (`20 minutes`), single-use CSPRNG tokens stored only as SHA-256 hashes, bound to that specific pending `approval_id`/`session_id` (no replay, no guessing, no cross-request approval; neither passwords nor reusable secrets ever appear in emails).<br>5. **Approve**: Unlocks ONLY that specific pending request, registers trusted device/IP for that account, records outcome + notifies admin; admin **still** must complete the separate Admin Security Password challenge.<br>6. **Reject**: Rejects that specific request, terminates ONLY that pending session (`DELETE FROM session`), keeps device untrusted, logs `critical` event, notifies admin.<br>7. **Timeout / No Response**: Expiry locks/invalidates **only that associated login session** (`status = 'expired'`, zero auto-approval) and never permanently locks the admin account; a fresh login creates a new `session_id` and fresh approval request.<br>8. **Gmail-Loss Recovery**: Authenticated server-side CLI / offline recovery procedure (`scripts/recover-admin-security.ts` and single-use backup recovery codes) documented in `SECURITY_INCIDENT_RESPONSE.md`. | `src/server/routes/security.ts`, `src/server/email.ts`, `src/server/admin-security.ts`, `docs/SECURITY_INCIDENT_RESPONSE.md` |
| **E. Admin Security Management UI** | Owner/Admin Security section exposes UI controls to view/revoke recognized devices (`admin_trusted_devices`), review recent login attempts (`login_history`), inspect & approve/reject pending security approval requests (`admin_login_approvals`), revoke active sessions, set/change the separate admin security password, and inspect security events (`security_events`). | `src/components/admin/AdminSettingsTab.tsx`, `src/components/admin/AdminDashboard.tsx` |

## 4. Rules for Every Code Change

Before modifying SELLORA:
1. Check whether auth, RBAC, Admin Security Password / Device-IP strict gate, CSRF, uploads, D1 batch transactions, SKU uniqueness/immutability, webhooks, error monitoring, or `/api/developer/*` scope isolation are affected.
2. Never return raw `err.message`, stack traces, SQL, or tokens in public/admin HTTP responses — route unexpected errors through `respondWithCapturedError()`.
3. Keep `error_monitoring_logs` and raw security telemetry out of shopper/admin UI; expose only sanitized references (`ERR-...` / `SEC-...`) or owner-level summaries.
4. Add or update unit/integration/security tests in `tests/sellora.test.ts` and update [`SECURITY_BASELINE.md`](./SECURITY_BASELINE.md) and [`KNOWN_ISSUES.md`](./KNOWN_ISSUES.md).
